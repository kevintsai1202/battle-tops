# Battle Tops — 3D 戰鬥陀螺 設計草案

## 已確認的決定（2026-09-29）

- 平台：Web，Three.js + Vite + TypeScript，陀螺物理自寫（純函式、可單元測試）。
- 日語語音：Fish Audio `s2.1-pro-free` 預先生成台詞音檔放 `public/voice/`，缺檔時退回 `speechSynthesis`（2026-10-01 追加全中文版與中文語音，見文末「語言切換」）。
- 範圍：1P vs CPU 完整一場，先拿 3 分獲勝（已由下方「3 對 3 賽制」取代）。
- 風格：動畫霓虹風（暗色競技場、Bloom、發光軌跡、反白衝擊幀、集中線）。

## 模組

| 路徑 | 職責 |
| --- | --- |
| `src/sim/` | 純邏輯：陀螺狀態、碗形場地、碰撞衝量、轉速衰減、爆裂／出場／停轉判定、計分、發射時機換算。固定步長 1/120 s，亂數可指定種子。 |

## 規則

- 停轉（Spin Finish）1 分；出場（Over Finish）、爆裂（Burst Finish）2 分；先拿 3 分勝（已由下方「3 對 3 賽制」取代）。
- 四種陀螺：攻擊（高攻、低持久）、防禦（重、抗擊退）、持久（轉速衰減慢）、平衡。
- 對戰中玩家可用方向鍵小幅推移；撞擊累積必殺量表，滿了按 Space 放必殺技（cut-in + 喊招）。
- 發射：倒數「3、2、1、ゴー・シュート！」，在 ゴー 時按下，時機越準初始轉速越高。

## 手機支援（2026-09-29；觸控操作已由下方「手機滑動操作」取代）

- **觸控操作**：左下虛擬搖桿（推移，方向相對鏡頭，與 WASD 相同）、右下「必殺」按鈕（量表滿才亮、每回合一次）；發射沿用「點畫面任意處」。搖桿向量換算（死區、截斷）寫成純函式並單元測試。
- **何時顯示**：偵測到觸控（`(any-pointer: coarse)` 或第一次 `pointerType === 'touch'`）才顯示，只在倒數與對戰階段出現；說明文字改成觸控版。
- **選角**：觸控時第一下選取並預覽、再點一次同一張決定。
- **版面**：矮螢幕（橫向手機，高度 ≤ 520px）時 HUD 與選角卡片改成精簡版；直向螢幕以加大 FOV 補償水平視野，標題畫面提示「橫向遊玩效果較好」。
- **防誤觸**：`touch-action: none`、關閉長按選字與選單、禁止雙擊縮放與下拉回彈。
- **效能**：觸控裝置 DPR 上限 1.5、Bloom 用 1/3 解析度、陰影貼圖 512。
- **驗收**：Playwright 手機模擬（橫向與直向、hasTouch），用 pointer 事件拖曳搖桿確認控制向量、點必殺按鈕確認發動，並檢查選角卡片與 HUD 沒有超出畫面。真機效能無法在 headless 驗證。

## 3 對 3 賽制（2026-09-30，取代「先取 3 分」）

已與使用者確認的規則：

- 賽前雙方各挑 3 顆，四選三不重複；玩家點選的順序就是第 1、2、3 戰的出場順序。
- CPU 的 3 顆在選角時公開，出場順序保密，每戰開打前才揭曉。
- 每戰只打一回合：停轉 1 分、出場 2 分、爆裂 2 分加給勝者；雙方同時倒下（平手）則該戰重打同一組。
- 三戰打完比總分；總分平手進入延長賽：玩家從自己 3 顆中再挑 1 顆、CPU 隨機挑 1 顆，打一回合決勝（平手重打）。

實作：

- `src/sim/team.ts`：純邏輯（建立對戰、目前對陣、記錄結果、平手重打、進入延長賽、判定勝者、CPU 隨機組隊），單元測試。
- 選角畫面改成組隊：點卡片加入／取消（卡片顯示 1、2、3 順序），湊滿 3 顆按「出陣！」；鍵盤 ←→ 移動、Enter 選取或取消、滿 3 顆時 Enter 出陣、Backspace 退回上一顆。
- HUD：總分與「BATTLE n/3」／「延長賽」，雙方陣容小圖示（目前出戰、已出戰與得分）。
- 每戰開打前大字「BATTLE n　A VS B」；延長賽跳出三選一；結果畫面列出每一戰的對陣與終結方式。
- 新增 4 句主播語音：第一／第二バトル、ファイナルバトル、延長戦。

## 難度（2026-09-30）

使用者確認：簡單／普通／困難三檔，在組隊畫面上方切換，瀏覽器記住上次選擇。預設普通。

| 難度 | 發射滿分區間 | 降到最低力道的誤差 | 最低力道 | CPU 發射力道 | CPU 使用必殺頻率 |
| --- | --- | --- | --- | --- | --- |
| 簡單 | ±0.15 s | 0.6 s | 0.8 | 0.60～0.80 | 0.3 倍 |
| 普通 | ±0.10 s | 0.5 s | 0.65 | 0.72～0.95 | 1 倍 |
| 困難 | ±0.05 s | 0.4 s | 0.5 | 0.85～1.00 | 1 倍 |

依據：CPU 對打模擬（16 組合 × 40 場，玩家守中並適時放必殺），「一般玩家」（晚 0.1～0.3 秒按）回合勝率約為簡單 84%、普通 76%、困難 42%；熟練玩家（±0.06 秒）三檔都約 76～83%，困難檔靠技術仍可贏。

實作：`src/sim/difficulty.ts` 定義三檔；`launchSpinRatio` 改吃判定視窗參數（預設維持原本的嚴格判定）；`cpuThink` 加必殺頻率參數；鍵盤 1／2／3 也能切換。

## 陀螺名鑑、屬性與必殺技（2026-09-30）

使用者確認：

- 名稱：**致敬改名**。類型、旋轉方向、屬性、外形、招式風格參考原型，遊戲內用改寫過的名字（專案先前為避開商標已改名 Battle Tops，GitHub Pages 公開）。
- 至少 16 顆有名的陀螺；保留原本 4 顆原創，共 20 顆，四種類型各 5 顆。
- 每顆陀螺的必殺技**效果各不相同**。

### 基本屬性 → 能力值

每顆陀螺填六項基本屬性（`BaseStats`）：攻擊、防禦、持久、重量（公克）、爆裂抵抗、機動，除重量外 1～10 分。物理能力值全部由 `src/sim/stats.ts` 的 `derivePhysics` 推導，不手填：

| 能力值 | 公式 | 範圍 |
| --- | --- | --- |
| 攻擊力 | 0.75 + 0.095 × 攻擊 | 0.85～1.7 |
| 防禦力 | 0.8 + 0.07 × 防禦 | 0.87～1.5 |
| 持久力（衰減除數） | 0.8 + 0.05 × 持久 | 0.85～1.3 |
| 最高轉速 | 270 + 5 × 持久 | 275～320 |
| 質量 | 0.5 + 重量 / 80 | 重量 25～80 g |
| 半徑 | 0.28 + 0.0015 × 重量 | |
| 爆裂抵抗（爆裂量除數） | 0.55 + 0.09 × 爆裂抵抗 | 5 分 = 1 |
| 驅動力 | 0.45 + 0.555 × 機動 | 1.0～6.0 |
| 巡航速度 | 1.0 + 0.4 × 機動 | 1.4～5.0 |
| 摩擦 | 0.15 + 0.05 × 防禦 + 0.01 × 機動 − 0.01 × 持久 | |

係數先以原創四顆校準（代入它們的屬性會得到原本手調的數值），再為了 20 顆的平衡把攻防持久的範圍收窄、質量隨重量的變化變小（範圍太寬時防禦 10、持久 10 的陀螺勝率 80% 以上）。`tests/stats.test.ts` 檢查原創四顆的推導值與舊值差距在 25% 內。

另外兩項不在六項屬性裡：

- **類型**：決定 CPU 走位（攻擊型追擊、防禦守位迎擊、持久守位閃避、平衡看轉速優劣）與卡片分類。
- **旋轉方向**：`spinDir` 取自陀螺本身（原本雙方固定右旋）。左旋對右旋時接觸面速度抵銷，彈開較輕、貼身互磨；吸轉效果對異向旋轉加倍。渲染時右旋從上方看為順時針。

「遊戲採用」與「換算」不同的地方是平衡調整：

- 重量：原型多在 31～41 g，原創四顆是 40～64 g。輕的陀螺在碰撞中一面倒吃虧，所以致敬陀螺的重量拉到 38～63 g，保留相對輕重（例：滅世魔神最重 63 g、原型 Diablo 輪是 Metal Fight 最重的輪）。
- 機動與爆裂抵抗：Burst、X 以外的世代沒有這兩項，依軸心類型估計（平頭軸／橡膠軸機動高、尖軸與球軸低）。
- 攻防持久：依 `npm run balance` 報表，勝率偏離太多的陀螺在原型值 ±1～2 內調整（冥鐮死神從 89% 調下來、凱旋武神與左旋攻擊型調上去）。

練習場 20×20 組合各 6 場的勝率範圍：33%（凱旋武神）～64%（吸魂魔龍）。

### 必殺技：基本動作的組合

`Buff` 從固定四種改成倍率組（攻、防、質量、衰減、摩擦、推移、巡航、爆裂傷害、吸轉、反擊、力場），`effAttack` 等函式讀倍率。每顆的必殺技是基本動作序列（`SpecialStep`），由 `src/sim/specials.ts` 的 `runSpecial` 依序執行：

| 動作 | 效果 |
| --- | --- |
| dash／brake | 朝對手突進、急停 |
| spin／repair | 回復轉速、修復爆裂量 |
| drain | 隔空吸取對手轉速（自己得到一半） |
| shove／pull | 衝擊波推開範圍內的對手、把對手拉近 |
| reverse | 反轉旋轉方向（雙旋） |
| warp／blink | 瞬移到對手背後、瞬移回中央 |
| buff／hex | 自己獲得增益、對手受到減益 |

每顆另有 `cue`（close／far／lowSpin／danger）告訴 CPU 何時放必殺。單元測試確認 20 顆在同一個初始狀態下發動後的結果兩兩不同，並跑每顆的鏡像對戰確認回復型必殺不會讓回合拖不完。

新增 16 句必殺技語音（Fish Audio 生成，Whisper 聽寫確認），原創四顆沿用舊檔（`p_special_attack` 等）。語音播放改成「單句缺檔就那一句用瀏覽器語音合成」，新增台詞還沒生成時不會沒聲音。

## 場地（2026-09-30）

使用者確認：練習場（原本的碗形場）之外，增加實際的戰鬥盤與三個特殊場地（火山、冰川、積水），要實際影響陀螺走向；在組隊畫面選一個場地（含隨機），整場三戰都用同一個場地。

`ArenaSpec`（`src/sim/arena.ts`）同時驅動物理與畫面，機關畫在實際作用的位置。五個場地半徑都是 3.2，鏡頭與特效尺寸共用。

| 場地 | 物理 | 畫面 |
| --- | --- | --- |
| 練習場 | 原本的參數 | 藍色霓虹格線 |
| 標準戰鬥盤 | 碗形較陡（0.072）；r > 2.55 為極限軌道：切線加速 + 往內分量（只往切線加速時陀螺會貼著外圈繞、打不到對手），機動越高加速越多，軌道上巡航上限 ×1.7；出場口 2 窄 1 寬 | 金色齒紋軌道帶（流動） |

| 積水 | 中央半徑 1.55 的水池：速度被拉向逆時針水流（阻力隨深度增加）、驅動力 ×0.6、轉速衰減 ×1.9；高速入水發出濺水事件 | 水面（波紋旋轉表示水流方向）、濺水 |

- 模擬新增 `hazard` 事件（erupt／splash／pillar），遊戲層轉成特效、音效與鏡頭震動。
- CPU 守位依場地：積水守在水池外緣、火山守在溝槽；守圓環時目標是環上「對手那一側」的點，否則兩顆持久型各守一邊整場碰不到。
- 燈光只建一次、切換場地時換主題色；場館群組可以整個釋放重建。
- 各場地的強弱傾向（20×20 組合各 6 場）：火山偏攻擊型、冰川出場終結大增且偏防禦、積水偏持久型、標準戰鬥盤偏防禦。當作場地特色保留。
- 耐久測試：練習場 400 組合全跑；四個特殊場地各抽 80 場；另有 20 顆的鏡像對戰。全部單元測試約 3 秒。

## 拉發射台（2026-09-30）

使用者確認：點一下發射太簡單，改成拉發射台。

- 力道 = 時機分 ×（難度保底 + 拉條品質），限制在 0.5～1。拉條品質 = 0.55 × 速度 + 0.45 × 長度。
- 長度：往下拉的距離加上 0.35 倍的橫向距離，拉到畫面短邊的 45% 為滿。速度：任兩個取樣點間隔至少 50 ms 的最快一段，每秒 3 個畫面短邊為滿（避免單一抖動取樣算出超高速）。往上拉不算。
- 瞄準：彈弓式，往左下拉陀螺往右飛，±35°。螢幕左右換成模擬角度時看發射時的鏡頭方向決定正負號。拉條時顯示拉線、POWER 條、瞄準角度與場上的瞄準箭頭。
- 難度保底：簡單 0.8、普通 0.68、困難 0.55。
- Space 保留為退路：只看時機，最高 85%，方向固定。展示模式只看時機。
- 按住超過「ゴー」0.6 秒自動放手；只點一下（沒拉）＝保底力道。
- 發射階段不顯示觸控搖桿（手指要拿來拉）。
- CPU 發射角度隨機 ±0.35 rad。
- 判定邏輯是純函式（`src/sim/launcher.ts`），單元測試涵蓋長度、速度、方向、往上拉、抖動、保底與上限。headless 瀏覽器的滑鼠事件間隔大，e2e 量到的拉速偏低（約 0.2），e2e 只檢查有量到速度。

## 必殺集氣（2026-09-30）

使用者要求：集氣更快、更常看到必殺；每顆陀螺集氣速度不同，並做平衡測試。確認的目標：5～10 秒集滿。

改之前的問題（練習場 20×20 組合各 3 場量測）：量表只靠撞擊強度累積，強度含表面速度差，左旋對右旋時互相抵銷，所以左旋三顆幾乎集不滿（蒼嵐青龍 0/60、雷皇龍 0/60、吸魂魔龍 3/60 回合）；攻擊型大多在集滿前就分出勝負（約 1/3 回合集滿）。

做法（`src/sim/physics.ts`）：

- `SpecialDef.charge`：每顆的集氣時間（5.5～8 秒），越強的必殺越慢。
- 量表同時靠時間與撞擊累積，兩者都除以集氣時間（`addCharge`）：
  - 被動：完全不撞時在「集氣時間 × 1.3」秒集滿（`PASSIVE_FILL`）。
  - 撞擊：依正面衝擊速度（法線方向）累積，與旋轉方向無關；單次上限避免一撞就滿。
  - 用過必殺就不再累積（每回合限用一次不變）。
- 吸轉效果（`spinSteal`）改成依正面衝擊速度打折：左右旋貼身互磨時每一步都有微小接觸，不打折會疊加成大量吸轉（雷皇龍、吸魂魔龍因此過強）。

平衡：必殺幾乎每回合都放得出來之後，必殺本身的強弱主導勝率，所以依平衡報表調整了多數必殺的倍率與集氣時間（數值見 `src/sim/tops.ts`）。`npm run balance` 報表多印每顆的集氣時間、集滿時間中位數與「有放出必殺的回合比例」。

（最終各場地的數字見下方「可替換零件 → 機動影響推移與突進」之後的重調結果。）

改之前練習場勝率 31～68%。

## 可替換零件（2026-09-30）

使用者確認：攻擊環固定（決定外觀、類型、必殺技），重心盤與軸心可換；備用零件每種只有一件，同一支隊伍的三顆不能同時用同一件；換了之後雷達圖立刻更新。

- `src/sim/parts.ts`：零件型錄（6 種盤、8 種軸）與隊伍零件狀態的純函式（`equip`、`release`、`spareHolder`），單元測試涵蓋每種一件、換回原廠歸還、離隊歸還、同型等於原廠、不改傳入物件。
- 屬性 = 攻擊環 + 盤 + 軸。每顆陀螺的原廠盤與原廠軸參考原型的零件型態（例：暴嵐天駒 105RF → 標準盤＋橡膠平頭軸、幻星獵戶 B:D → 外緣盤＋軸承軸）；攻擊環的屬性由「原本的屬性 − 原廠盤 − 原廠軸」反推，所以**原廠組合的屬性與物理值和加入零件前完全相同**（測試逐顆比對）。
- `clampStats` 是唯一的範圍限制（1～10、重量 25～80 g），雷達圖與 `derivePhysics` 共用，兩邊不會不一致。
- `buildSpec(id, loadout)` 產生套用零件的規格；身分（代號、名稱、外觀、必殺）不變，語音與畫面照舊。遊戲層只有玩家陀螺用 `playerSpecOf`，CPU 一律原廠。
- 零件選單只給隊伍中的陀螺；被隊友用掉的備用零件在選單中停用並標出裝在誰身上。沒有記在瀏覽器（每場重新選）。

### 機動影響推移與突進

第一版零件報表發現：拿機動換防禦／持久的軸心幾乎是純賺（蒼嵐青龍換針頭軸勝率 +51 個百分點）。原因是 CPU 靠推移追擊，而推移力道和機動無關，機動只影響巡航速度。改成機動決定推移靈活度與必殺突進速度（`mobility()`：機動 10 分為 1、0 分為 0.4），尖頭、針頭這類低機動的軸心推不太動、也衝不快。

這個改動影響全部 20 顆的原廠平衡，所以重新調了一輪必殺強度與集氣時間。

重調後的最終結果（`./scripts/balance-all.ps1 -Games 6`，20×20 組合各 6 場）：

| 場地 | 勝率範圍 | 集滿時間中位數 | 有放出必殺的回合 |
| --- | --- | --- | --- |
| 練習場 | 39.6～64.6% | 5.3～9.7 秒 | 75～100% |
| 標準戰鬥盤 | 34.6～69.2% | 5.5～9.7 秒 | 86～100% |
| 火山 | 36.0～66.4% | 6.0～9.2 秒 | 86～100% |
| 冰川 | 41.2～61.5% | 6.3～9.4 秒 | 38～95%（出場終結多、回合短） |
| 積水 | 24.3～90.7% | 5.4～9.4 秒 | 81～100% |

改之前練習場勝率 31～68%。積水場持久型一面倒（冰原狼 90.7%、疾風鳳 84.2%），是既有的場地傾向，但比集氣改版中途量到的 86% 更極端，列為待處理。

### 零件平衡報表

`npm run balance:parts`（`scripts/parts-report.test.ts`）：每顆陀螺換上每件備用零件後，對全部原廠陀螺的勝率（每個種子兩個座位各一場），和原廠組合相比。最終結果（練習場，每組 6 場）：

- 每件零件的平均影響：−7.9～+0.6 個百分點（軸承軸最差、針頭軸最好）。原廠組合是調過的，換零件多半是取捨而不是升級。
- 單換一件的最大提升 +11.5（暴嵐天駒＋護鎖盤）；勝率最高的組合 71.8%（烈焰龍＋護鎖盤，原廠已 65.5%）。
- 開發過程的坑：一開始報表奇數種子坐 A 座、偶數種子坐 B 座，原廠勝率和平衡報表差很多（玄武甲 13% vs 40%）。座位（開場位置與發射力道的亂數順序）影響很大，必須每個種子兩個座位都打。雙方發射力道相同時，練習場 A 座勝率約 44%（推測和出場口不對稱有關），是既有的偏差，沒有在這次處理。

## 手機滑動操作（2026-09-30，取代虛擬搖桿與必殺按鈕）

使用者要求：拿掉搖桿，滑動螢幕控制方向；必殺改成三指觸控。確認的手感：拖曳持續推移＋快甩短衝刺兩者並用。

- `GestureTracker`（`src/ui/touch.ts`，純邏輯、單元測試）：
  - 拖曳：按下處為浮動原點，往哪拖就往哪推，拖越遠越用力；手指超出半徑時原點跟著移動，往回拉方向立刻反轉。
  - 快甩：看放手前最後一次移動的速度（最後 0.1 秒內移動 ≥ 畫面短邊 10%、速度 ≥ 每秒 2 個短邊），而且最後一次移動要在放手前 0.1 秒內（甩完停住再放不算）。放手事件晚到、位置和最後一次移動相同時，不把放手點算進速度。
  - 三指：第三隻手指按下的瞬間發動（不等放開），全部手指放開前只發一次。
  - 只有「畫面上沒有其他手指時按下的那一指」是拖曳手指；拖曳期間出現過第二指，放手就不算快甩（避免三指必殺誤觸衝刺）。
- `BattleSim.dash`：快甩衝刺，速度 3.2 × 機動倍率、消耗 3% 轉速、冷卻 0.9 秒，發出 `dash` 事件（畫面上小衝擊波與發射聲）。CPU 與鍵盤沒有衝刺。
- 多指時 `touchstart` 的 `preventDefault` 只在對戰中掛上：非 passive 的 touchstart 會讓每次觸控都等主執行緒，不該拖慢發射台的拉條。系統層級的三指手勢（部分 Android 的三指截圖、iPad 的三指編輯）擋不掉，列在 README 的已知限制。
- 畫面：按下處的圓圈與手指圓點；畫面下方的提示平常顯示操作方式，必殺集滿時變成「必殺 READY！三指觸控發動」並發光。
- 順手修正：拉發射台的取樣只保留最近 1.5 秒時會連起點一起丟掉，拉得慢時長度被算短；改成起點一定保留（`trimPullSamples`）。
- e2e：headless 的 CDP 觸控在機器忙時一個事件要將近 1 秒，做不出真正的快甩；三指與拖曳用 CDP 原生觸控驗證，快甩改在頁面內連續送觸控類型的 pointer 事件驗證接線。

## 操作教學（2026-10-01）

使用者要求：製作操作教學指引，要有動畫與語音，一步一步指引怎麼操作。

使用者的決定：遊戲內互動教學（做到了才進下一步）；涵蓋組隊兩步、拉發射台、推移衝刺必殺、計分與終結方式；語音只有中文；
標題按鈕進入，第一次打開時提示（原本想做成「點開始時跳出詢問」，但所有 e2e 都是點標題就預期進組隊，改成標題上不擋開打的提示）。

- 流程（`src/tutorial/flow.ts`，純邏輯、單元測試）：四章十二步，每一步有標題、電腦版與手機版的解說語音（字幕就是台詞去掉語氣標記）、
  示範動畫的種類、聚光圈目標與「做到了沒」的判定。遊戲每幀把狀態（已選幾顆、出場順序或零件有沒有改、發射有沒有拉條、推移累計秒數、
  衝刺與必殺次數、是否分出勝負、「下一步」按鈕）餵給流程；累計數字以進入這一步時為基準。發射沒拉條（拉條長度 < 0.25，只點一下也會量到長度 0）回傳 retry。
- 畫面（`src/ui/tutorial.ts`）：面板（章節、第幾步、標題、字幕、示範動畫、重聽／跳過這步／下一步／結束教學）放在聚光圈目標的另一半邊；
  聚光圈用超大的 box-shadow 壓暗其他地方，不擋點擊。面板本身 `pointer-events: none`、只有按鈕可以點：拉發射台時手指或滑鼠從面板上拖過去也照常。
  示範動畫全用 CSS（手指點擊與波紋、發射環縮小與往下拉、滑動、快甩殘影、鍵帽依序亮起、三指、三種終結的小動畫）。
- 遊戲端（`src/game/game.ts`）：
  - 固定練習場、簡單難度的發射判定（結束後還原）；從發射開始對手不動也不放必殺。
  - 發射：解說講完前把倒數停在開場介紹（也不接受拉條與 Space）；沒拉條就提示後重來這一戰（`startRound`，會播「重新再戰」與「（重賽）」）。
  - 發射到必殺的步驟保護雙方：每一步模擬後把轉速維持在五成以上、爆裂量五成以下；被撞出場在 finish 事件就攔下（不播終結大字與主播），提示後重來這一戰。
  - 必殺那一步直接把量表集滿；計分那一步把對手轉速降到兩成，很快分出勝負；得分直接記上（賽況仍標示剛打完的這一戰），不進下一戰。

### 指引改畫在實際畫面上（2026-10-01）

使用者回饋：教學只有語音和面板裡的小動畫，要在實際的大畫面上指出該點哪裡。
使用者的決定：選陀螺時依序指推薦的三顆（選別顆也算）；面板裡的小動畫拿掉；發射先示範一次再輪到玩家。

- 每一步改成「大畫面指引」（`GuideKind`：tap／drag／swipe／flick／keysMove／keysDash／keySpace／three／arrow／none），電腦與手機各一種；
  目標改成只指一個元素：推薦的下一顆陀螺（`RECOMMENDED`＝烈焰龍、鐵壁龜、疾風鳳，名鑑第一排；`targetOf` 依已選的決定）、下一步、第 2 戰的 ▲、軸的選單、出陣、必殺量表。
- 手指（觸控）與滑鼠游標（電腦）是 SVG，指尖對準容器的定位點；動作依每幀的時間推進（不用 CSS keyframes），主執行緒卡住時不會跳掉或彼此錯開。
  鍵帽放在自己的陀螺下方，會被面板蓋到就放上方；箭頭從自己的陀螺指向對手。指引全部 `pointer-events: none`。
- 發射示範用真的發射台：倒數暫停中 `updateLaunch` 不會畫發射台，教學每幀用 `launchMeter` 畫一份腳本化的拉條（3.2 秒一輪：按下、往下拉到畫面短邊 45%、外圈對上時放手跳出 GO SHOOT），
  手指跟著拉條的末端；開場介紹的大字收起、遊戲本身的發射台說明字在教學中隱藏。重來的那一次不示範（只提示按住的位置）；拉條中手指收起。
- 目標換了就 `scrollIntoView({ block: 'nearest' })`（手機的零件選單在可以捲動的詳細資料裡）。
- e2e：每個要點的步驟檢查手指的位置在目標裡、`elementFromPoint` 是目標本身（指引不擋點擊）、聚光圈只框住目標；
  指引容器是 0×0 的定位點，Playwright 會當成看不見，看得見與否要檢查裡面的手指。鍵帽與面板不重疊。

## 手機必殺按鈕與多指防誤推（2026-10-01）

使用者回饋：手機上用三指發動必殺時很容易拖到畫面。
原因：先落下的那一指變成推移手指，手指一滑過死區（約畫面短邊的 3%）就推動陀螺；必殺發動後到全部手指放開前也一直在推。
系統層級的三指手勢（部分 Android 的三指截圖、iPhone 的三指編輯）網頁擋不掉。
使用者的決定：必殺集滿時出現大按鈕，三指也保留。

- 手勢（`src/ui/touch.ts` 的 `GestureTracker`，單元測試）：
  - 拖曳手指按下後 `PUSH_DELAY`（0.12 秒）才開始推移；只影響推移，取樣與快甩的判定不變（測試：按下到放手 0.06 秒的快甩仍算）。
  - 拖曳期間出現第二指就停止推移、浮動原點的圓圈收起，直到全部手指放開為止（原本「拖曳手指繼續控制」的測試改成新的行為）。
  - `vector(now)` 用現在的時間判斷是否已過等待時間（手指按著不動時沒有新事件），遊戲每幀傳入。
- 必殺按鈕（`#special-btn`）：手機對戰中、必殺集滿時才出現在右下角（右手拇指的位置，92 px、發光脈動）；
  pointerdown 就發動，事件不往外傳（`window` 上的滑動推移與多指偵測收不到，不會帶動推移）。觸控提示改成「點右下角的按鈕（或三指觸控）」。
- 教學：手機版的必殺那一步改成手指指著必殺按鈕（`targetOf` 依輸入方式決定：電腦框量表、手機指按鈕；`TutorialCtx` 加上 `input`），
  解說改成「點右下角發光的必殺按鈕…三根手指同時點一下畫面也可以」並重錄；拿掉三指示範（`three` 指引）。
- 驗證：單元測試（第二指停止推移到全部放開、三指陸續放下不推、0.12 秒後才推、快甩不受影響）；
  e2e：手機橫向三指陸續放下時推移向量與陀螺的推移都是 0、圓圈收起；按鈕集滿前不出現、點一下發動且不帶動推移；直向按鈕在畫面內、不蓋到觸控提示；教學手機版指著按鈕並照著點。
